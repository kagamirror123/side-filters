# 設計判断と却下した案

Side Filters の設計上の決定と、その理由、却下した案をまとめる。
実装前（2026-09-02）に決めた内容なので、実装で覆したら必ずここを更新する。

## そもそも自作した理由

もとは [eetann/amazing-searcher](https://github.com/eetann/amazing-searcher)（最終更新 2021-11、★9、ライセンス無し）を使っていた。
Google 検索結果の右カラムに「期間」「言語」「Recipe」のチップを出す拡張で、期間チップを日常的に使っていた。
2021 年の SERP 構造を前提にしているため、いまはナレッジパネルが無い検索でカードが検索結果に被る。

同じ位置・同じ操作感で現役の代替は無いことを 2026-09-02 に調査して確認した（再調査不要）。

- uBlacklist（★6.6k・現役）は検索結果からサイトを除外する拡張で用途が違う
- Google Search Time Filter（64 ユーザー）は画面端のサイドバー、Google Search by Date は検索ボックス下の横バー、Recen（63 ユーザー）は URL 書き換えで SERP 上に常設 UI を持たない。いずれも「結果の右にカードで並ぶ」体験にならない
- Web Search Navigator（★954、`z`+`h/d/w/m/y` で期間切替）は MV2 のまま Chrome ウェブストアから削除済み。後継の Search Navigator（1,000 ユーザー・MV3）はキーボード操作専用で期間切替が無い
- Chrome 標準の検索ショートカット（`tbs=qdr:w` 付き URL を登録）は「検索してから絞り直す」流れにならない

ライセンスが無いので、旧拡張のコードと同梱データは一切流用しない。参考にしたのは「右カラムの先頭に出る」という体験だけ。

## 置き場所と Grid 配置

**採用: `#rhs` があればその先頭に置く。無ければ `#rcnt` の Grid に自前の列を足す。**

2026-09-02 に実測した SERP の構造（Chrome 152、日本語 UI、ビューポート 2560px）:

| 要素                     | grid-column                                                 | 位置と幅     |
| ------------------------ | ----------------------------------------------------------- | ------------ |
| `#rcnt`                  | grid コンテナ。22 列 = `210px` + `36px`×20 + 余り、gap 20px | x=0 w=2545   |
| AI による概要の枠        | `1 / -1`                                                    | 1 行目、全幅 |
| `#center_col`            | `2 / span 12`                                               | x=230 w=652  |
| `#rhs`（ナレッジパネル） | `span 7 / -2`                                               | x=958 w=372  |

### AI 概要の横（設定で選べる、既定はオフ）

AI 概要の出方は 2 通りある。

- **`#center_col` の中に入る場合**（例: `typescript satisfies operator`）: カードは従来どおり右に並ぶので、結果として AI 概要の横に出る
- **`#rcnt` 直下に `grid-column: 1 / -1` の枠として出る場合**（例: `確定申告 やり方`）: 1 行目を全幅で占めるので、カードは 2 行目（`#center_col` の横）に落ちる

後者のとき、AI 概要の**中身の右端はちょうど x=1330**（`#rhs` の右端と同じ）で、そこから先は Grid のいちばん右の列にあたる空きになる。
x=958〜1330 は AI 概要の**引用元カード**（e-Tax、国税庁 …）で埋まっているので、そこには置けない。置けるのは x=1350 から先。

この空きにカードを上げるかは設定で選べる（`placement`、既定は `results` = 従来どおり）。`wide` を選んでも、次の両方が揃ったときだけ使う。

- 1 行目を全幅で占める枠がある（無ければ空きが生まれない）
- いちばん右の列にカードが収まる（372px 以上）

列の幅は `ウィンドウ幅 − 1350px`（固定列 210 + 36×20 と gap 20×21 の合計）なので、**ビューポートがおよそ 1750px 以上**でないと入らない。
1440px では 75px しかない。つまりカードの場所は一定しない。これは設定画面に明記して選ばせる。

**置き方: 負のマージンで引き上げる。`grid-row: 1` は使わない。**

`grid-row: 1` を指定すると、`grid-row: auto` の Google の枠が 2 行目へ押し出され、ページ全体が枠の高さぶん下にずれることを実測した。
いちばん右の列に普通に置いたうえで、`margin-top` に「枠の上端との差」を入れて引き上げれば、行の取り合いが起きず Google の要素にも触らない。
引き上げ量は content script が実測して `--wide-offset` に入れ、枠の高さが変わる（「もっと見る」）たびに `ResizeObserver` で測り直す。

`#rhs` はナレッジパネルが出る検索でしか存在しない。
無いときは、`#center_col` の直後に `grid-column: span 7 / -2` の要素を挿すと x=958 / w=372 に着地することを、実際のページで確認した。
`grid-row` は auto のままでよい（自動配置で `#center_col` と同じ行に入る）。

旧拡張は `#center_col` の `margin-left + width + 60px` を計算して左マージンを付ける方式で、Grid になった今の SERP では x=712 に落ちる。
これが「検索結果に被る」不具合の正体。

幅は固定値にせず列幅いっぱい（いまは 372px）にする。Google が列幅を変えても追随する。

セレクタは `#rcnt` / `#center_col` / `#rhs` の 3 つの id にだけ依存する。
どれかが無くなったら何も描かない（壊れた表示を出すより出さない方がよい）。

## 見た目を Google に寄せる判断

**採用: Google のカードと同じ文法で描き、拡張が居ることを意識させない。**

実測したダークテーマの値:

| 項目                         | 値                                                    |
| ---------------------------- | ----------------------------------------------------- |
| 背景 / 文字                  | `rgb(34 36 42)` / `#e8e8e8`                           |
| フォント                     | Arial 14px（見出し 21〜22px、cite 12px `#bdc1c6`）    |
| リンク                       | `#99c3ff`                                             |
| カード                       | 角丸 8px、影 `1px 1px 15px 0 rgb(23 23 23)`、枠線なし |
| `<meta name="color-scheme">` | `dark light`                                          |

ライトテーマは Google の既知の値（背景 `#fff`、文字 `#1f1f1f`、リンク `#1a0dab`、補助 `#474747`、境界 `#dadce0`）から起こし、ライトのプロファイルで実測して直す。

- テーマは `body` の背景色の輝度で判定し、シャドウホストに `color-scheme` を付けて CSS は `light-dark()` で書く。`prefers-color-scheme` は Google のテーマ設定と一致しないので使わない
- 2026-09-02 に実測したチップ（ダーク、検索結果下の関連チップ）: 高さ 32px、`500 12px/16px Arial`、枠 `1px solid rgb(68 71 70)`、角丸ピル、余白 `7px 15px`、文字はリンク色、背景なし。「ツール」はいまはドロップダウンになっていてチップは出ない
- 選択中は Google 自身が絞り込みに使う青の tonal 塗り（ライト `#d3e3fd` 地に `#041e49`、ダーク `#004a77` 地に `#c2e7ff`）
- ホバーは `light-dark(#f2f2f2, rgb(48 49 52))`、フォーカスは 2px の輪郭（`light-dark(#1a73e8, #99c3ff)`、offset 2px）
- 見出しに 16px のアイコン（時計・地球、Material Symbols）を添えて、何の選択肢かを一目で分ける

## 選択肢の並べ方

**採用: 区切り線でつないだ 1 本のピル（segmented control）。先頭に「全期間」「全言語」を置く。**

単独のチップを 7 つ並べると 340px の列で 3 段に折れ、最後の行に 1 つだけ残る。次の 3 つで 1 行に収めた。

- ラベルから「以内」を落とす。見出しが「期間」なので `24時間` `1週間` `1か月` `6か月` `1年` `3年` で意味が通る。`w1` `m6` のような省略表記は読めないので採らない
- 「すべて」チップをやめ、先頭の区切り「全期間」「全言語」にする。常にどれか 1 つが光るので、いまの状態がピルだけで読める。見出し右の「クリア」も検討したが、絞り込み中しか出ず戻し方が見えないので却下
- 区切りの左右の余白は 8px。単独チップの 15px より詰まっているが、つないだ 1 本の中なので不自然に見えない

2026-09-03 に実 Chrome で実測した幅（日本語 UI、既定プリセット）: 期間 321px / 言語 146px。カードの内側は 340px。
カードの高さは 3 段の 252px から 172px になった。

`data-all` は「全期間」「全言語」に付く印。いまは他と同じ青で塗るが、「絞り込み中だけ青」にしたくなったらここに中立色を足すだけで切り替わる。

### オンとオフだけの控えの置き場所

**採用: そのセクションの見出しの行に、一回り小さいチップとして置く。**

平らに 1 行へ並べる案と比べて高さはほぼ変わらず（実測 270px 対 272px）、何に効く控えなのかが位置で読める。

- 期間の見出し: 日付順（ニュースのときだけ）
- 検索語の見出し: 完全一致・フレーズ
- 言語の見出し: なし

除外は**トークン入力欄**（枠の中にチップが並び、末尾に打てる欄がある形）。
「＋ 除外」チップを押すと入力欄に化ける案は却下した。チップは押すと決まった動作をするもので、化けるものではない。

### 収まらないときの退避

プリセットを増やす、長いラベルを付ける、UI 言語が変わる、Google が列幅を変える、といった理由で 1 行に入らなくなったら 3 列の格子に落とす。

- 判定は個数ではなく実寸。`data-measuring` を一瞬付けて姿を必ず連結ピルに戻し、`scrollWidth <= clientWidth` を見る。ラベルの長さもフォントも UI 言語と設定で変わるので、数えても当たらない
- マークアップは 1 つ。`data-layout` を `track` / `grid` で切り替えるだけで、CSS が 2 つの姿を作る
- 列幅が変わったら測り直す。`ResizeObserver` は `ul` 自身ではなく親を見る（姿が変わるたびに再発火して往復しないように）
- 格子のチップは列幅いっぱいに広げる。幅が揃うので、はみ出した結果の並びには見えない
- 見出しは「期間」「言語」の 2 つだけ。ラベルは i18n
- カード右上に設定へのリンク（歯車）を 1 つ置く

## 機能範囲

**採用: 期間・言語に加えて、検索語まわり（完全一致・フレーズ・除外）。Recipe は作らない。**

- 期間: `tbs=qdr:h` / `d` / `w` / `m` / `y`。`qdr:d3` `qdr:m6` `qdr:y3` のように数字を後置すると倍数になる。プリセットは設定で編集できる（既定は 24時間・1週間・1か月・6か月・1年・3年 あたりを実装時に決める）
- 言語: `lr=lang_ja` / `lang_en` など。プリセットは設定で編集でき、セクションごと非表示にもできる
- 「すべて」チップで解除。選択中のチップは現在の URL の `tbs` / `lr` から判定して塗る
- リンク先は現在の URL をベースに `tbs` / `lr` だけ差し替える。`q` や `tbm`、`hl` などは維持する。例外は `start`（ページ番号）で、絞り込みを変えたら落とす（3 ページ目で期間を変えて新しい結果の 3 ページ目に飛ばないように。Google 自身のチップも同じ挙動）
- `tbs` は `qdr:w,sbd:1` のようにカンマ区切りで複数の部分を持つ。差し替えるのは期間の部分（`qdr` と、排他のカスタム期間 `cdr` / `cd_min` / `cd_max`）だけで、`sbd`（日付順）などは残す
- 出す画面は「すべて」「ニュース」「動画」。`tbm=vid` は `udm=7` に転送されることを実測で確認した。旧来の `tbm`（空 / `nws` / `vid`）と、新しい `udm`（空 / `14` ウェブ / `12` ニュース / `7` 動画）の両方で見る。画像・ショッピング・地図・AI モード（`udm=50`）には出さない
- Recipe（検索語に応じて公式サイト等へのリンクを出す機能）は使っていなかったので落とした。データモデルと設定画面が半分以上軽くなる

### 検索語まわり（2026-09-03 追加）

**採用: `q` を書き換える機能を入れる。ただし状態は一切保存せず、毎回 `q` から導出する。**

当初は「`q` は触らない」と決めていたが、`"完全一致フレーズ"` と `-除外` は実際に使うので入れた。
`q` に足したものを解除するとき「拡張が足したのか本人が打ったのか」を区別する必要があるのが元の懸念だったが、
**チップの状態を保存せず毎回 `q` を読んで導出すれば、その区別自体が要らなくなる**。

- **除外**: `q` の `-語` トークンをそのままチップにする。本人が手で打った `-foo` も同じチップに出る。× はそのトークンを消すだけ
- **フレーズ**: `q` の「除外でない部分」を引用符で囲む。押下状態は「除外でない部分がひとつの引用句か」で決まる。除外は囲みの外に残すので、除外とフレーズは同時に使える
- 演算子（`site:` など）・グループ化・既存の引用符を含む、または引用符が閉じていない検索語では**フレーズを無効化**する。半端に囲むと壊れるため
- 解析は `lib/query.ts`（引用符を尊重した分割・`-` の判定・組み立て直し）。純関数なので vitest で固める
- 組み立て直しは残ったトークンを空白 1 個で連結する。連続した空白は畳まれるが、意味は変わらない

### tbs の単独フラグ

- **完全一致**（`tbs=li:1`、同義語展開をやめる）: ウェブ検索で効くことを 2026-09-03 に実測（ツールが「完全一致」表示＋リセットが出る）
- **日付順**（`tbs=sbd:1`）: **ニュースでしか効かない**。ウェブ検索と動画では黙って無視されることを実測した（ツールに現れず、結果の並びも変わらない）。
  そのため日付順チップは `tbm=nws` / `udm=12` のときだけ出す。`udm=12` がニュースであることは未検証（外していても、Google のタブから来たときにチップが出ないだけ）

### 「ウェブ」（udm=14）を入れない理由

素のリンク一覧に戻す `udm=14` は人気があるが、カードには入れない。

- 絞り込みではなくタブの切り替えで、Google 自身がタブ行に持っている（`hl` を外したのと同じ理由）
- 意味のまとまりのどこにも入らず、置き場所が無かった。収まらないのは仲間ではないから
- 常時オンにしたい類の設定なので、Chrome の検索エンジンに `udm=14` 付き URL を登録するほうが合う。
  期間チップでショートカット案を却下したのとは、必要としているものが逆（あちらは「検索してから絞る」）

## データの持ち方

**採用: `chrome.storage.sync`。**

- content script から IndexedDB を使うと google.com のオリジンの DB になり、設定画面（拡張のオリジン）と共有できない。`chrome.storage` は両方から同じデータが見える
- `storage.onChanged` で設定変更が開いている SERP にも即反映される
- `sync` は端末間で同期され、Chrome の同期をオフにしていてもローカルで動く。設定は数百バイトなので上限（1 項目 8KB・全体 100KB）は問題にならない
- import/export は sync が肩代わりするので v1 では作らない

設定の形（案）:

```ts
interface Settings {
  terms: { label: string; qdr: string }[]; // 例: { label: "1週間", qdr: "w" }
  langs: { label: string; lr: string }[]; // 例: { label: "日本語", lr: "lang_ja" }
  showLangs: boolean;
  showQuery: boolean; // 検索語セクションをカードに出すか
  placement: "results" | "wide"; // カードを出す場所。既定は results
  theme: "system" | "light" | "dark"; // 設定画面の配色。既定は system
}
```

読み出し時に形を整える関数を 1 つ置く（壊れた項目だけ既定に戻し、配列の中の不正な要素は捨てる）。zod などのスキーマライブラリはこの規模では要らない。
既定のプリセットは 期間: `d` `w` `m` `m6` `y` `y3`、言語: 日本語・英語。ラベルは `_locales` から引くので UI 言語に従う（日本語なら「24時間」「1週間」…）。
ストレージの読み書きは WXT の `storage.defineItem("sync:settings")` に任せる（`watch` で `onChanged` の購読と解除が付いてくる）。

## 描画とライフサイクル

- content script は `https://www.google.com/search*` にだけ入る。2025-04 に Google が ccTLD（google.co.jp など）を google.com へ統合したので、ドメインはこれで足りる
- UI は WXT の `createShadowRootUi`（`cssInjectionMode: "ui"`）で Shadow DOM に閉じ込め、Google の CSS と互いに干渉しない
- `ui.autoMount()` でアンカーの出現を待ち、`wxt:locationchange` で URL が変わったら再描画する（Google はタブ切替を pushState で行うことがある）
- React 19 で描く。設定と URL は React の外で持ち、`root.render` を呼び直す。Effect はデータ取得には使わない（失敗しうる非同期が無い）が、描画後の実寸が要る「連結ピルが 1 行に収まるか」の判定にだけ `useLayoutEffect` を使う
- チップは `<a href>` にする（中クリックで新しいタブに開ける、キーボードで辿れる）。選択中は `aria-current="true"` で示し、CSS もこれを見る
- **カードの控えはすべて「押すと URL が変わってページが読み込み直されるリンク」**。だからオン・オフの控えにもスイッチやチェックボックスは使わない（その場で状態が変わるという別の意味になる）。設定画面のスイッチとは見た目も役割も分ける
- 除外の入力欄のキー入力は Google 側へ漏らさない（`createShadowRootUi` の `isolateEvents: true`）。Google は素の `/` などを拾う
- 「完全一致」「フレーズ」「日付順」は言葉だけでは何をするか分からないので、`title` で説明を出す。カードが狭いので `?` アイコンは置かず、チップ自身に持たせる
- フレーズは**検索語が 1 語のときは無効化**する。1 語を囲んでも「完全一致」とほぼ同じことしかせず、控えが重複するため。無効の理由は `title` で出し分ける
- 歯車は content script から `runtime.openOptionsPage` を呼べないので、background にメッセージを送って開いてもらう
- WXT は Shadow DOM の先頭に `:host{all:initial !important}` を入れる。host に効かせたい `display` / `grid-column` / `color-scheme` は自前 CSS で `!important` を付けて上書きする。テーマは host の `data-theme`、配置は `data-slot` で切り替える

WXT の落とし穴（vpn-on-demand で踏んだもの）:

- `publicDir` は srcDir ではなく root 基準。`srcDir: "extension"` なら `publicDir: "extension/public"` を明示する
- 生成される tsconfig に `jsx` が入らないので、ルートの tsconfig.json で `"jsx": "react-jsx"` を足す
- `options_ui.open_in_tab` は wxt.config.ts では効かない。entrypoint の HTML に `<meta name="manifest.open_in_tab" content="true">` を書く

## 設定画面

- kumo（`@cloudflare/kumo`）+ phosphor icons。vpn-on-demand のポップアップと同じ部品で揃える
- タブで開く。内容は「期間プリセットの編集」「言語プリセットの編集」「言語セクションの表示」の 3 つだけ
- 期間は `m6` のようなコードを直接打たせず、数（1 以上）と単位（時間・日・週・か月・年）の 2 つに分ける。`lib/url.ts` の `parseQdr` / `formatQdr` が qdr と往復する
- 言語コードは `lang_ja` 形式のテキスト入力。よく使うコードは `<datalist>` で候補に出しつつ、一覧に無いコードも手で入れられる
- 行の見出しは列見出しとして 1 度だけ出す。各入力欄には `aria-label` を付け、狭い幅（640px 以下）では列見出しをやめて各欄の上に戻す
- 保存は明示のボタンを置かず、変更の 400ms 後にまとめて書く。1 文字ごとに `storage.sync` へ書くと書き込み回数の上限に当たる
- 画面の状態が下書きで、storage には `normalizeSettings` を通った分だけが入る。ラベルを空にしている途中の行はカードから消えるが、編集は続けられる
- 配色は kumo のトークン（`--text-color-kumo-default` / `--color-kumo-base` など）に任せ、`data-theme="kumo"` を html に、`data-mode` を body に付ける。あわせて html の `color-scheme` も切り替える（スクロールバーなどブラウザ側が描く部分を揃えるため）
- テーマは「システム設定に従う（既定）/ ライト / ダーク」から選べる。効くのは**設定画面だけ**で、SERP のカードは Google の配色に合わせたまま。Google がライトなのにカードだけダークだと壊れて見えるため。system のときだけ `prefers-color-scheme` を見る（SERP のカードと違い、ここは拡張自身のページなのでこれでよい）
- 別の端末での変更は `storage.onChanged` で追わない。編集中に自分の書き込みが跳ね返って上書きし合うのを避けるため
- SERP 側のカードには kumo を使わない。標準 CSS が 124KB あり、検索のたびに読み込む場所には重い。カードは自前 CSS（数十行）で足りる

## i18n

- `browser.i18n` をそのまま使い、`extension/public/_locales/{en,ja}/messages.json` に置く。`default_locale` は `en`
- manifest の name / description も `__MSG_*__` で引く。ストア公開で英語を既定にするため
- 言語はブラウザの UI 言語に従う（拡張側で切り替えは持たない）

## 配布

- Chrome Web Store で公開する。`npm run zip` の出力を上げる
- CI は lint / fmt / typecheck / test / build。`v*` タグで zip を artifact にする
- ライセンスは MIT。プライバシーポリシーは `PRIVACY.md`（データ収集なし・外部通信なし）
- 権限は `storage` のみ。ホスト権限は content script の `matches` に含まれる google.com だけ

## テスト

- 単体（vitest）: URL の組み立て（`tbs` / `lr` の差し替えと他パラメータの維持）、選択中チップの判定、テーマ判定、設定の整形
- 配置: 上の表の構造を再現した最小の HTML フィクスチャで、「`#rhs` あり」「なし」の両方で正しい位置に入ることを確認する
- 手動: `.output/chrome-mv3` を読み込み、ナレッジパネルが出る検索（例: `python`）と出ない検索（例: `typescript satisfies operator`）、ライト / ダーク、`tbm=nws` で確認する
- Google の実ページは自動テストで叩かない（ボット判定に掛かる）

## 却下した案

| 案                                                 | 却下した理由                                                                                   |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `#center_col` の幅から margin を計算して右に寄せる | Grid 化した SERP で破綻した、現行の不具合そのもの                                              |
| カード幅を 350px 固定                              | 列幅が変わると余白や被りが出る。列幅いっぱいにする                                             |
| 「すべて」を単独チップとして先頭に置く             | 1 つぶん幅を食ううえ、選択中に青く塗られて「絞り込み中」に見える。連結ピルの先頭の区切りにした |
| 「クリア」リンクで絞り込みを解除                   | 絞り込み中しか出ないので、戻し方が見えない。「全期間」の区切りなら常にそこにある               |
| チップを 1 行にして横スクロール                    | 後ろのプリセットが隠れる。ワンクリックで絞る道具で、押す前にスクロールが要るのは本末転倒       |
| 収まるかを個数で判定                               | ラベルの長さもフォントも UI 言語と設定で変わる。描画後の実寸で見る                             |
| Recipe 機能                                        | 使っていない。データモデルと設定画面が倍になる                                                 |
| IndexedDB                                          | content script では google.com の DB になり設定画面と共有できない。この規模には過剰            |
| `storage.local`                                    | sync でもローカルで動くうえ端末間同期が付く。容量も足りる                                      |
| CSV の import/export                               | カンマを含む値が扱えない旧仕様。sync があるので v1 では不要                                    |
| Effect / zod                                       | 失敗しうる非同期も複雑なスキーマも無い                                                         |
| SERP 側で kumo を使う                              | 標準 CSS 124KB を検索ごとに読む。自前 CSS で足りる                                             |
| `prefers-color-scheme` でテーマ判定                | Google のテーマ設定は OS 設定と独立している                                                    |
| 既存拡張への乗り換え                               | 「結果の右にカードで並ぶ」体験を持つ現役の拡張が無い（上記）                                   |
